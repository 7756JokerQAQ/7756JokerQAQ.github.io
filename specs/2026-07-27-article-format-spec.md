## 2. 规范定稿

### 2.A 文章内部排版规范（逐篇统一）

**A1. Frontmatter（三件套）**
```yaml
---
title: "标题"                # 校正到与内容一致；与文件名解耦
description: "一句话摘要"     # 喂给首页 <DocCardList/> 卡片 + SEO，≤80 字
sidebar_position: N          # 控制本分类内排序
---
```
- `title` 校正规则：以文章实际主题为准（如 `Spring基础学习.md`→`Spring5 学习笔记`、`SDK的make.md`→`开发简易的 SDK`、`mainshi.md`→`面试题总结与回答`、`tools.md`→`常用工具类`）。具体逐篇定。
- 不加 `tags`（本地搜索已覆盖，YAGNI）。

**A2. 标题层级**
- 正文一律从 `##`（H2）起头；**正文中所有 `#`（H1）降级**为 H2 或更合适的层级。
- 严禁层级跳跃（H2 直接到 H4）；逐级递进。
- 面试题2 等用 H4 当顶级的，整体上提（H4→H2）。

**A3. 标题去编号化（纯语义）**
- 去掉标题行首的人工序号前缀：`1.` / `1.1` / `2.` / `1，` / `1、` / `\.` 等一律删除。
- 保留有语义的词。示例：
  - `## 1.线段树的原理` → `## 线段树的原理`
  - `## 1，JavaScript简介` → `## JavaScript 简介`
  - `#### 1.什么是 IOC` → `## 什么是 IOC`
  - `#### 4\. String 和 StringBuffer` → `## String 与 StringBuffer / StringBuilder`
- 编号信息若有导航价值（如「第 N 题」），融入标题文字而非用数字前缀。

**A4. 列表**
- 有序统一 `1.`（Markdown 自动编号）；无序统一 `-`。
- 消灭 `1、` `1，` `1)` `（1）` `(1)` 等变体；括号编号 `（1）(2)` 转为有序列表 `1.` `2.` 或保留为正文加粗小标题，视语境择优。

**A5. 代码块**
- 全部标注语言：` ```java ` / ` ```xml ` / ` ```bash ` / ` ```sql ` / ` ```text ` 等。
- 输出/无语义内容用 ` ```text `。

**A6. HTML 实体处理（⚠️ MDX 环境）**
- Docusaurus 用 MDX 解析，**正文里裸的 `<`/`>` 后跟字母或数字会被当作 JSX 标签，导致 `npm run build` 报 MDX 编译失败**（已踩坑：线段树 `2<3`、刷题篇 `i<j` 等）。
- 因此正文中表示「小于/大于」的 `<` `>` **必须保留为实体** `&lt;`/`&gt;`（或用行内代码反引号包裹）；`&amp;`→`&`、`&nbsp;`→空格 可正常还原。
- 代码块（` ``` `）和行内代码内部的 `<` `>` 不受影响，原样保留。

**A7. 不可见字符清除**
- 删除 U+200B/U+200C/U+200D/U+FEFF（零宽/BOM）、U+00A0（NBSP→普通空格）、段首多余全角空格。

**A8. `<!-- truncate -->` 位置统一**
- 置于首段摘要之后（用于列表/卡片摘要截断）。已有 `<!-- truncate -->` 的保留位置合理化。

**A9. 正文轻度润色（已授权）**
- 允许顺手理顺明显错乱、不通顺的语句；**不改变技术语义与代码**。改动以「读得通」为度，不做内容增删。

**A10. 重点加粗（有轻有重）**

- 对核心概念的首次定义、关键结论、重要术语适度**加粗**，让文章主次分明、有轻有重。
- 克制原则：单段不超过 1-2 处加粗；不整句整段加粗；已被行内代码 / 标题 / 链接承载的内容不重复加粗；避免满屏加粗反而丧失重点。

### 2.B 文章之间组织规范（侧边栏）

**B1. 排序**：每篇 frontmatter 用 `sidebar_position` 手控本分类内顺序（不靠文件名排序）。顺序按学习/阅读逻辑排（基础→进阶），逐篇定。

**B2. 分类元信息**：每个分类目录加 `_category_.json`：
```json
{ "label": "数据结构与算法", "position": 1, "collapsed": false }
```
- 五大分类 position：算法 1 / 后端 2 / 课程 3 / 面试 4 / 工具 5（与现有 sidebars.ts 顺序一致）。

**B3. 保留项**：`sidebars.ts` 的 autogenerated 结构不动；`docusaurus.config.ts` 中 diary 倒序逻辑不动。

### 2.C 图片迁移（CDN → 本地）

- 目标：把剩余 65 张 `https://cdn.jsdelivr.net/gh/7756JokerQAQ/picodemoo/img/<basename>` 下载到 `static/img/cos/<basename>`，引用改为 `/img/cos/<basename>`。
- 命名沿用 basename（与既有 270 张一致）。
- 涉及 10 篇：AVL树(5) LINUX(10) 并查集(4) 计算机组成原理第二三章(15) 计算机系统概述(9) 插入排序(1) MyBatis(3) 线段树(2) SpringMVC笔记(8) Spring基础学习(8)。
- 失效图（404）沿用既有占位策略：替换为占位提示，记录在迁移清单。
- 补全 alt 文本（用图片上下文或邻近标题）。

## 3. 执行策略

**先 1 篇样板 → 用户确认风格 → 批量套用**，分批 commit：
1. 样板篇：《线段树》（含算法类典型问题：标题编号、H1 混入、实体、CDN 图）。
2. 用户确认后，按分类批量：算法 → 后端 → 课程 → 面试 → 工具，每分类一个 commit。
3. 图片迁移作为独立 commit（或并入对应分类 commit）。
4. 全部完成后 `npm run clear && npm run build` 验证（遵守项目「构建前清缓存」约定），本地 `npm run start` 抽查。

---

## 4. 范围外（YAGNI）

- 不重构站点架构、不动 navbar、不开通被注释的导航项。
- 不引入 tags 系统、不接 Algolia。
- 不重写文章技术内容、不补充缺失章节。
- blog/ 目录空置，本次不动。

---

## 5. 风险与回滚

- **风险**：批量改标题可能导致站内锚点链接失效——本项目文章间几乎无相互锚点引用，风险低；执行时 grep 确认。
- **风险**：CDN 图下载失败（jsdelivr 不可达）——记录失败清单，占位处理，不阻断其余工作。
- **回滚**：每分类独立 commit，可按分类 revert。
